# Using issues in this playground

Issues are a lightweight place to describe a question, a bug, or a small piece of work before changing files.

## Writing a useful issue

Include enough context for another person to understand the request:

- **Title:** state the task or problem clearly.
- **Context:** explain what you observed or what outcome you want.
- **Steps:** for a bug, list how to reproduce it.
- **Expected result:** describe what should happen.
- **Evidence:** attach logs or screenshots when they help, and remove secrets first.

Keep one issue focused on one topic. If work is larger, split it into smaller issues and link them so progress is easy to follow.

## Keeping issue status current

Use labels to make the kind of work visible, and assign an owner only when someone has agreed to take it on. Close an issue when its work is complete, or when the request is no longer relevant; leave a short comment explaining the outcome. If a pull request addresses an issue, link the issue from the PR description so GitHub can connect the work.
